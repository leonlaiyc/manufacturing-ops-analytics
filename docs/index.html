A transparent, explainable simulation decision engine: every decision number is validated against a known baseline and remains traceable.

晶圓廠 AI 營運決策引擎

1

Diagnose

Read a public 4TU job-shop manufacturing production log, then summarize case paths, DFG, cycle time, waiting time, and rework signals.

診斷

讀取公開 4TU.ResearchData 的 job-shop manufacturing production log，整理 case path、DFG、cycle time、waiting time 與 rework 訊號，作為真實製造紀錄的流程診斷示範。

2

Model

Build a fixed-seed synthetic fab with batch furnace and re-entrant litho, then test each method against known bottlenecks and injected anomalies.

建模

建立固定 seed 的合成 fab，包含 batch furnace 與 re-entrant LITHO，再用已知瓶頸和刻意注入的異常檢查方法是否抓得到答案。

3

Decide

Compare capacity, maintenance, dispatching, and yield options with CRN-paired what-if runs, each tied to traceable assumptions and KPIs.

決策

把加機台、維修時機、派工規則與良率取捨放進 CRN paired what-if，每次輸出都保留假設、seed 與 KPI 結果。

When metrics conflict

If the priority is shortening cycle time, the better choice may be paying higher cost for a larger cycle-time improvement.

If short-term financial return is the priority, the better choice may be the option with the strongest net saving or fastest payback.

If both matter, first define the minimum cycle-time improvement required, then choose the most cost-effective option that meets that threshold.

當指標衝突時

如果優先目標是縮短 cycle-time，較好的選擇可能是支付較高成本換取較大的 cycle-time 改善。

如果優先目標是短期財務回報，較好的選擇可能是淨節省最高或回收最快的方案。

如果兩者都重要，先定義最低需要的 cycle-time 改善門檻，再選擇符合門檻且最具成本效益的方案。

Operational impact, investment cost, and business objective must be evaluated together to find the best answer for the current situation.

營運影響、投資成本與商業目標必須綜合評估，在不同的當下情境找出最佳解。

02

Slow-drift monitoring: turning detection time into decision value

When equipment degrades slowly, output metrics may not warn immediately; by the time output falls, congestion cost has already accumulated. This monitoring design uses EWMA, a control-chart method sensitive to small persistent drift, as the baseline. Labeled anomaly scenarios measure detection delay and false-alarm rate, then convert alert timing into cost still avoidable. In a 160-day synthetic backtest, an output-only monitor stays silent over the whole horizon; EWMA alerts on day 84, meaning this experiment's EWMA method can avoid the extra degradation cost that would accumulate over the following 76 days.

慢性劣化監控：把偵測時間轉成決策價值

設備緩慢劣化時，產出指標可能尚無警訊，等產出下滑，早已累積了一定的壅塞成本。本專案的監控設計以 EWMA 對小幅持續漂移敏感的管制圖方法作為基線，用標註好的異常情境量測偵測延遲與誤報率，再把警報時間點換算成仍可避免的成本。在 160 天的合成回測中，只看產出的監控整段期間沒有發出任何警報；EWMA 在第 84 天發出警報，也就代表在此實驗中使用EWMA方法可以節省後面76天因劣化產生的額外成本。

03

One agent, four classes of fab operations questions

One agent contains analysis modules for four operations questions: how to add tools, maintenance timing, dispatching rules, and output-yield trade-offs. Each analysis records scenario, seed, assumptions, and KPI results in the same format, so the numbers are traceable. This means a future AI agent can produce decision memos by calling the same what-if engine, with traceable results instead of freely generated answers.

一個agent，回答四類 fab 營運問題

一個agent內包含：該如何加機台、維修時機判斷、派工規則、產出與良率取捨，四個營運問題的分析流程模組。每次分析都用相同格式留下 scenario、seed、假設與 KPI 結果，讓數字可以追溯。這代表未來若要讓 AI agent 產出決策備忘錄，它呼叫的是同一套 what-if engine，且結果有跡可循，而不是自由生成答案。
