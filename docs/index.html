Manufacturing Operations Analytics & Decision Support

Turning production data into decisions a team can act on — and challenge

Find the station that's really holding the line back, catch a machine degrading before it hurts, and know which fix is actually worth the money — built on a transparent, validated simulation of a semiconductor-style production line.

把產線數據，變成團隊能執行、也能被檢驗的決策

找出真正拖累產線的那一站、在機台劣化造成損失前先抓到、並判斷哪一個改善方案 真的划算——整套方法建立在一個透明、可被驗證的「半導體式產線」模擬之上。

1

Diagnose

Process-mine a real production log to reconstruct the actual flow and see where time is lost.

診斷

用 process mining 把真實生產紀錄還原成實際流程,看出時間到底 耗在哪裡。

2

Model

Build a transparent factory where bottlenecks, degradation, and improvement methods can be simulated and tested, validated with Little's Law (0.2% gap between predicted and measured WIP).

建模

打造一個透明工廠，讓瓶頸、劣化與改善方法能被模擬測試，並以 Little's Law 驗證 （預測與實測 WIP 誤差僅 0.2%）。

3

Decide

Put capacity-improvement options into what-if scenarios, so the team can compare trade-offs faster and more efficiently.

決策

把產能改善方案放進 what-if 情境，讓團隊更快、更有效率的比較取捨。

01

Local metrics show candidates, not the final answer

Local metrics identify which stations deserve attention, but they do not directly answer which capacity addition improves the whole line most. FURNACE is slow per batch and processes the most lots per run, while LITHO has the highest utilization. The decision needs a system-level what-if comparison.

局部指標能指出候選站點，但不是最後答案

局部指標可以告訴我們哪些站點值得注意，但不能直接回答「加哪一站的產能，對整條線改善最大」。 FURNACE 單批加工時間最長、每次運轉可處理最多 lots；LITHO 的稼動率最高。因此還需要用整體系統的 what-if 比較來判斷。

Investment-stress scenario: station-specific tool-cost assumptions. LITHO $40k, FURNACE $8k, DEPO $5k, METRO $2k. These are illustrative station-specific cost assumptions used to test decision sensitivity, not real factory prices.

Calculation: Net cost change = scenario total cost - baseline total cost. Total cost includes processing cost (tool busy-hours × illustrative processing rate), waiting / congestion cost (lot queue-wait hours × illustrative holding rate), and added tool cost (number of added tools × illustrative tool cost). Negative saves versus baseline; positive costs more.

計算方式：淨成本變化 = 方案總成本 − 基準總成本

總成本包含：

  • 處理成本（工具忙碌時數 × 示意處理費率）
  • 等待 / 壅塞成本（lot 排隊等待時數 × 示意持有費率）
  • 新增機台成本（新增機台數 × 示意機台成本）

（負值代表相對基準省錢；正值代表成本增加）

Processing consumes tool time, energy, labor, and maintenance resources. Waiting creates WIP burden, longer lead time, and congestion risk.

處理會消耗工具時間、能源、人力與維護資源；等待會造成 WIP 負擔、lead time 變長與壅塞風險。

Break-even added-tool cost asks: how expensive can the added tool be before the option stops being net-saving? In this run the thresholds are LITHO $32.0k, FURNACE $9.7k, DEPO $3.3k, and METRO $0.6k.

新增工具的損益平衡成本回答的是：新增工具可以多貴，才不會讓方案從淨節省變成淨增加？本次結果為 LITHO $32.0k、FURNACE $9.7k、DEPO $3.3k、METRO $0.6k。

When metrics conflict

If the priority is shortening cycle time, the better choice may be paying higher cost for a larger cycle-time improvement.

If short-term financial return is the priority, the better choice may be the option with the strongest net saving or fastest payback.

If both matter, first define the minimum cycle-time improvement required, then choose the most cost-effective option that meets that threshold.

當指標衝突時

如果優先目標是縮短 cycle-time，較好的選擇可能是支付較高成本換取較大的 cycle-time 改善。

如果優先目標是短期財務回報，較好的選擇可能是淨節省最高或回收最快的方案。

如果兩者都重要，先定義最低需要的 cycle-time 改善門檻，再選擇符合門檻且最具成本效益的方案。

Operational impact, investment cost, and business objective must be evaluated together to find the best answer for the current situation.

營運影響、投資成本與商業目標必須綜合評估，在不同的當下情境找出最佳解。

Why cost rises: as LITHO slows down, each lot spends more time waiting in the system. Output may remain stable for a while, but queue wait and WIP burden increase. The illustrative cost model converts that extra waiting and congestion into cost.

為什麼成本上升：LITHO 變慢後，每個 lot 在系統中等待的時間變長。Output 可能短時間仍然穩定，但 queue wait 和 WIP 負擔會增加。示意成本模型把額外等待與壅塞轉換成成本。

Cost estimate: run the same line in two versions, one without degradation and one where LITHO slowly degrades from day 30. The cumulative cost gap by day 160 is the extra cost caused by degradation. Because EWMA alerts on day 84, the cost that has not yet accumulated after day 84 is the cost that could be avoided if action is taken after detection. In the reference run, that avoidable amount is about $236,942 of $249,164, or 95.1%.

成本估算：同一條產線跑兩個版本，一個沒有劣化，另一個從 day 30 開始讓 LITHO 慢慢劣化。到 day 160 的累積成本差，就是這次劣化造成的額外成本。因為 EWMA 在 day 84 alert，day 84 之後尚未累積的成本，就是偵測後採取行動可能避免的成本。在 reference run 中，可避免金額約為 $236,942，占 $249,164 的 95.1%。

Another advantage is that this workflow can be backtested: it checks whether a drift detector finds the problem before output makes it obvious, then estimates how much future cost early action can avoid.

另一個優勢是這個流程可以 backtest：先檢查 drift detector 是否能在 output 明顯變差前找到問題，再估算及早行動可以避免多少後續成本。
