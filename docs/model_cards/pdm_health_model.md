# Model Card: Predictive Maintenance (PdM) Health Model

## Purpose

Flags an elevated risk of unscheduled tool failure ahead of time, using
simulated sensor signatures, so a maintenance action can be considered
before a breakdown interrupts production.

## Data

Synthetic only. Generated by the project's hand-built discrete-event
simulator plus a sensor simulation layer (`src/equipment/sensor_sim.py`)
producing self-generated tool sensor signatures correlated with simulated
degradation episodes. All synthetic generation uses a fixed seed. No real
fab, tool, or sensor data is used anywhere in this project.

## Method

Gradient boosting classifier (scikit-learn `GradientBoostingClassifier`), an
owner-approved exception to the project's default interpretable-methods
rule, used to measure detection quality against known synthetic ground
truth, never to claim real predictive power. The comparison partner is an
EWMA control-chart detector (`src/monitoring/detectors.py`), the project's
default interpretable baseline, so the value the gradient-boosting model
adds (or does not add) over a fully explainable method is stated explicitly
rather than assumed. The train/test split is by episode (a degradation
episode never appears in both splits), and SHAP values check the model is
keying off the two wired sensor channels rather than a simulation artifact.

## Metrics

Measured on synthetic ground truth (notebook 08):

- Gradient boosting held-out AUC: 0.7871
- Gradient boosting: mean detection delay 11.29 days, false-alarm rate
  0.0163, precision 0.943
- EWMA baseline: mean detection delay 9.86 days, false-alarm rate 0.0598,
  precision 0.883
- Honest comparison: EWMA detects slightly faster; gradient boosting cuts
  the false-alarm rate substantially at a small delay cost.

## Intended use

Illustrating a predictive-maintenance detection-quality comparison (simple
interpretable baseline vs a more flexible model) on a synthetic dataset with
known injected ground truth. A teaching and demonstration artifact for the
simulation-in-the-loop pattern this project documents.

## Out-of-scope uses

Not validated on any real fab, tool, or sensor stream. Must never be used to
predict, schedule, or make maintenance decisions about real equipment. The
sensor signatures are self-generated by this project's own simulator, so a
claim of predictive power would be circular; the metrics above measure
detection quality against a known synthetic label, nothing more.

## Failure modes

- Sensor signatures are simulated to correlate with the injected degradation
  by construction; a real sensor stream could have a fundamentally different
  signal-to-noise structure the model has never seen.
- Episode-level splitting prevents leakage within this dataset, but the
  model has only seen this simulator's specific failure signatures.
- Gradient boosting can overfit spurious correlations in a small synthetic
  sample; the numbers above are a single fixed-seed measurement, not a
  distribution over seeds.

## Trust boundary

Do not trust an alert in isolation. Compare it against the EWMA baseline's
alert on the same window: a gradient-boosting-only alert with no EWMA
support is weaker evidence than an alert both detectors agree on. Check
`src/equipment/pdm_check.py` and `src/equipment/maintenance_check.py` pass
before trusting output from this module, and check
`src/dataquality/dq_check.py` (event-log schema contract) passes on the
input log, since a corrupted log can produce a plausible but wrong health
signal. This model has no conformal interval of its own; its reliability
gate is the honest detection-quality comparison against EWMA, not a
coverage guarantee.
