# Model Card: Virtual Metrology (VM)

## Purpose

Predicts a lot's metrology reading (a virtual, simulated stand-in for a
post-process inspection measurement) from upstream process variables
available before the METRO step, so risk can be flagged earlier than a
physical inspection would allow.

## Data

Synthetic only. Generated by the project's hand-built discrete-event
simulator (`src/generator/factory_generator.py`), a stylized single-product
wafer-fab loop with a re-entrant LITHO step, fixed seed (default
configuration seed 42). The metrology reading is a synthetic ground-truth
latent defect probability plus Gaussian noise (`src/quality/yield_model.py`,
`QualityConfig`, noise sigma 0.01 by default). No real fab data is used
anywhere in this project.

## Method

Ordinary least squares, hand-built with `numpy.linalg.lstsq` (no
scikit-learn), fit on features known before METRO: post-LITHO queue times
and violation flags for both LITHO visits, LITHO process durations for both
visits, ETCH process duration and its standardized excess, and one-hot
indicators for which physical LITHO tool ran each visit. The split is
time-based (train earliest, evaluate latest), not random, since a random
split would leak shared tool-state and queue dynamics across nearby lots.

Split conformal prediction intervals (`src/dataquality/conformal.py`) wrap
the fitted model: a calibration split, disjoint from training, supplies the
absolute-residual quantile used to build a constant-width interval around
each point prediction, at 90 percent nominal coverage.

## Metrics

Measured on synthetic ground truth (notebook 07):

- Test R-squared (vs a train-mean baseline): 0.9315
- Risk-ranking AUC (predicted reading vs defects greater than 0): 0.7278
- OLS coefficients recover the ground-truth risk drivers (queue-time
  violation coefficients both positive, matching the injected effect)
- Conformal coverage and interval width are re-measured per run by
  `src/dataquality/reliability_check.py` (GATE 3, GATE 4); see that script's
  output for the current run rather than treating a number here as fixed.

## Intended use

Illustrating a virtual-metrology workflow (leakage-safe feature
engineering, interpretable regression, calibrated uncertainty) on a
synthetic dataset with known ground truth. A teaching and demonstration
artifact for the simulation-in-the-loop pattern this project documents.

## Out-of-scope uses

Not validated on any real fab, tool, or process. Must never be used to
predict, control, or make decisions about a real semiconductor
manufacturing line. The metrics above describe recovery of a synthetic,
hand-specified ground truth, not real-world metrology behavior.

## Failure modes

- The linear model cannot capture nonlinear or interaction effects beyond
  what was hand-specified in the synthetic ground truth.
- The time-based split assumes deployment is close to the most recent
  training window; a regime change (see `src/dataquality/drift.py`)
  invalidates this until refit or recalibrated.
- Conformal intervals are constant-width, not adaptive to local difficulty:
  they can be too wide or too narrow locally while averaging correctly.

## Trust boundary

Do not trust a point prediction alone. Check the conformal interval width
for the current run: `src/dataquality/reliability_check.py` GATE 3 confirms
empirical coverage stays within [0.85, 0.96] of the 90 percent nominal
target, and GATE 4 confirms the interval widens when noise increases; a run
where either gate fails should not be trusted until investigated. Also check
`src/dataquality/dq_check.py` (schema contract) passes on the input log
first: a corrupted log can silently produce a wrong metrology reading.
